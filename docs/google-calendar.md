# Googleカレンダー連携

Googleカレンダーの予定を、Nora Scheduleのカレンダーに取り込んで表示します(Google → Nora の一方向)。要件定義書の FR-12.1〜12.6 にあたります。

さらに、カレンダーを1つ選んで双方向に同期することもできます(下の「双方向同期」、issue #3・#4)。

## できること

- 自分のGoogleアカウントで認可し、連携を許可・解除する
- アカウント内のカレンダーから、取り込むもの・表示するものを選ぶ
- 繰り返し予定、終日予定、複数日予定を表示する(繰り返しはGoogle側で展開済みの1回ずつを取り込む)
- 取り込んだ予定は薄い色+左端の色帯で表示し、Noraの予定と区別する。ドラッグ・編集・削除はできない
  - クリックで詳細(読み取り専用)、右クリックで「Googleカレンダーで開く」「自分の予定として複製」
- 起動時、「今すぐ更新」ボタン、一定間隔(5分〜3時間)で自動更新する
- 通信できないときは前回取り込んだ予定をそのまま表示し、最終更新時刻とエラーを設定画面に出す
- 取り込んだ予定にも通知を出せる。設定の「取り込んだ予定の通知」で、なし(初期値)/ Googleの設定どおり / 5・10・30・60分前 から選ぶ
  - 「Googleの設定どおり」は、予定ごとのポップアップ通知のうち最も早いものを使う。予定がカレンダーの既定を使っている場合は、カレンダーの既定の時間を使う。メール通知は対象外
  - 「Googleの設定どおり」に切り替えた直後は、次の更新でGoogleの通知時間が取り込まれてから通知されるようになる

取り込む範囲は、今日の180日前から400日後までです。

## 初回の準備(Google Cloud側)

配布用の共通クライアントは用意していないため、自分用のOAuthクライアントを作ります。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る
2. 「APIとサービス」→「ライブラリ」で **Google Calendar API** を有効にする
3. 「OAuth同意画面」(Google Auth Platform)を設定する。ユーザーの種類は「外部」
4. **公開ステータスを「本番環境」(In production)にする**(「対象」→「アプリを公開」)。下の注意を参照
5. 「認証情報」→「認証情報を作成」→「OAuthクライアントID」→ 種類は **デスクトップ アプリ**
6. 表示されたクライアントIDとクライアントシークレットを控える

### 公開ステータスについての注意

- 公開ステータスが「テスト」のままだと、Googleが発行する認可(リフレッシュトークン)は **7日で失効** します。カレンダーの権限はこの対象なので、毎週つなぎ直しが必要になります
- 「本番環境」にしても、自分だけで使う範囲ならGoogleの確認(審査)を受ける必要はありません。確認を受けていないアプリとして動き、接続するときに「このアプリは Google で確認されていません」という画面が出ます。「詳細」→「(アプリ名)に移動(安全ではないページ)」で進めます
- 確認を受けていないアプリは、使える人数が通算100人までに制限されます。自分や身近な数人で使うなら問題ありません
- 認可が切れたり取り消されたりしたときは、設定画面に「接続し直してください」と表示されます。「接続し直す」を押すと、保存済みのクライアント情報でもう一度認可します

(2026年10月にGoogleの公式ドキュメント「Using OAuth 2.0 to Access Google APIs」と「Manage App Audience」で確認した内容です。条件は変わることがあります)

## 接続

1. Nora Scheduleの「設定」→「Googleカレンダー」に、クライアントIDとシークレットを貼り付けて「接続」
2. ブラウザでGoogleの同意画面が開くので、許可する(「このアプリは Google で確認されていません」と出たら、「詳細」→「(アプリ名)に移動」)
3. 「Googleカレンダーと接続しました」と表示されたらタブを閉じてアプリに戻る

最初はメインのカレンダーだけが取り込まれます。ほかのカレンダーは一覧のスイッチで選んでください。

## 双方向同期

Googleカレンダーを1つ選ぶと、そのカレンダーとアプリの予定を双方向に同期します。初期状態はオフです。

### 使い方

1. 設定 →「Googleカレンダー」→「双方向同期」の「変更を許可…」を押す。ブラウザで、予定の変更を許可する同意画面が出る(取り込みだけのときは読み取り権限しか求めていないため)
2. 同じ欄で、同期するカレンダーを選ぶ。選べるのは、自分が予定を変更できるカレンダーだけ。始める前に、送る件数・取り込む件数・1つにまとめる件数を確認する画面が出る
3. やめるときは「しない(取り込みのみ)」を選ぶ。アプリとGoogleの予定はどちらもそのまま残り、つながりだけが切れる

### 何が起きるか

- 始めると、アプリの予定がすべてGoogleへ送られ、そのカレンダーの予定はアプリの予定として取り込まれる(1年以上前に終わった予定は取り込まない)。タイトル・日時・終日・繰り返しが同じ予定が両方にあれば、重複させずに1つにつなぐ
- 以降は、自動更新・「今すぐ更新」のたびに、Googleの変更を取り込んでからアプリの変更を送る。アプリで予定を作る・直す・消すと、約4秒後に送る
- 同じ予定を両方で変更していたときは、新しく変更した方を残す。上書きされた側の内容は履歴に残る(下記)
- 同期する項目は、タイトル・日時・終日・場所・メモ・繰り返し。色・タグ・通知・リンク・「完了」の印はアプリだけのもので、Googleには送らない。Googleから来た予定の色は既定の色になる
- 繰り返し予定は、繰り返しの規則(RRULE)と除外日(EXDATE)で送受信する。Googleで1回分だけ変えた予定は、アプリでは別の予定として表示し、元の繰り返しからはその日を除く
- 「第2火曜日」のように、アプリで表せない繰り返しはアプリの予定にせず、取り込んだ予定と同じく閲覧のみで表示する。設定画面にその件数を出す
- 同期するカレンダーを別のものに変えると、前のカレンダーとのつながりは切れ、アプリの予定は新しいカレンダーへ送られる

### 上書き・削除の履歴

同期で上書き・削除された内容は、30日間「上書き・削除の履歴」(双方向同期の欄)から戻せます。記録するのは次の3つです。

- Googleでの新しい変更で、アプリの予定が上書きされた(アプリ側の古い内容)
- Googleで削除されたため、アプリの予定を消した(消した予定)
- アプリでの新しい変更を優先し、Google側の変更を捨てた(Google側の内容)

「戻す」と、その内容がアプリの予定に復元され(消えていた予定は新しく作られ)、次の同期でGoogleにも送られます。色・タグ・通知などアプリだけの項目は、予定が残っていればそのまま保ちます。

### 仕組み

- 予定の変更は、SQLiteのトリガーで検出する。同期する項目が変わると `events.updated_at` が更新され、`gsync_at`(最後に送った時点)より新しい予定を送る
- Googleとつながった予定を消すと、`gsync_tombstones` テーブルに記録し、次の同期でGoogleからも消す
- 上書き・削除した内容は `gsync_history` テーブルに残し、30日を過ぎたものは次の同期で消す
- Googleからは、前回からの差分だけを受け取る(同期トークン)。トークンが期限切れになったときは全件を取り直し、Googleにもう無い予定を消す(アプリで変更中のものは残す)
- 予定の送信には、アプリが作るID(`nora` + 端末ごとの文字列 + 予定番号)を使う。送信が途中で切れても、同じ予定が2件できない

## データの扱い

| 何を | どこに |
|---|---|
| クライアントシークレット、リフレッシュトークン | OSの資格情報ストア(Windows資格情報マネージャー / macOSキーチェーン)。SQLiteにもバックアップにも入らない |
| クライアントID、選んだカレンダー、更新間隔、最終更新時刻、双方向同期のカレンダーと同期トークン | SQLiteの `settings` テーブル(キー `gcal`) |
| 双方向同期の対応表(GoogleのID、最後に送った時刻) | SQLiteの `events` テーブルの列(`google_id` など)と `gsync_tombstones` テーブル |
| 取り込んだ予定 | SQLiteの `gcal_events` テーブル(オフライン表示用のキャッシュ。Google側の通知時間も含む) |

- 求める権限は `calendar.readonly`(読み取りのみ)です。双方向同期を使うときだけ、`calendar.events`(予定の変更)を追加で求めます
- 接続するまで、Googleとは一切通信しません。「連携を解除」でトークンを失効させ、資格情報と取り込んだ予定を削除します
- バックアップを別のPCで復元すると、トークンは移らないため「もう一度接続してください」と表示されます

## 実装の場所

- `src-tauri/src/gcal.rs` — OAuth(ループバック+PKCE)、API呼び出し、キャッシュ、Tauriコマンド
- `src-tauri/src/gsync.rs` — 双方向同期(変更の検出、繰り返し規則の変換、取り込みと送信)
- `src/lib/gcal.svelte.ts` — 状態と自動更新タイマー
- `src/components/GoogleCalendarSettings.svelte` — 設定画面
- `src/components/ExternalEventModal.svelte` — 取り込んだ予定の詳細(読み取り専用)
